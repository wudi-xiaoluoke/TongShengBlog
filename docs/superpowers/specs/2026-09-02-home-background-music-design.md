# 首页首次访问背景音乐设计

## 目标

访问者第一次进入博客首页时，从两首本地 MP3 中随机选择一首并播放。音乐只自动触发一次；刷新首页、离开后返回首页或重启浏览器，都不会再次自动播放。

浏览器可能阻止有声自动播放。此时页面等待用户第一次点击、触摸或按键，再尝试播放。播放器采用与首页手账风一致的“迷你便利贴”样式，只显示暂停或继续图标。

## 范围

本次实现包括：

- 将 `音乐包/木馨.mp3` 与 `音乐包/罗小涵.mp3` 作为 Spring Boot 静态音频资源提供。
- 首页随机选择且只播放其中一首；歌曲结束后停止，不循环，也不续播另一首。
- 浏览器持久化首次播放状态。
- 自动播放受阻时，在首次用户交互后重试。
- 为当前播放提供精简的暂停/继续按钮。
- 将首次访问状态封装为可替换边界，方便未来接入账号系统。
- 为纯播放逻辑编写自动化测试，并验证首页资源与模板集成。

本次不包括账号、登录、跨设备同步、音量调节、歌曲切换、播放列表和全站播放器。

## 技术方案选择

### 采用：浏览器 `localStorage`

`localStorage` 可跨页面、刷新和浏览器重启保存状态，最符合当前“一个浏览器只自动播放一次”的要求，也不需要提前引入用户系统。

### 未采用：`sessionStorage`

它只在当前标签页会话内有效。关闭标签页后再次访问会重新播放，无法达到持久的一次性体验。

### 未采用：后端 HTTP Session

Session 会过期，也可能因服务重启或 Cookie 清理而变化。当前没有登录身份时，它并不比 `localStorage` 更可靠，还会增加服务端状态。

## 架构与组件

### 首页模板

首页模板声明音频候选资源，并包含默认隐藏的迷你便利贴按钮。按钮只有在本次页面已经开始播放音乐后才显示，避免后续访问出现无意义的播放器。

### 首次访问状态存储

前端通过一个小型状态存储接口读取和写入“首页背景音乐已播放”：

- `hasPlayed()`：判断是否已经播放过。
- `markPlayed()`：在音乐真正开始播放后记录状态。

当前实现使用 `localStorage`。未来接入账号系统时，可以替换这两个操作，使其调用用户资料接口或读取服务端下发状态，而无需改动选曲与播放控制逻辑。

### 播放协调器

独立的前端模块负责：

1. 查询首次访问状态。
2. 从候选歌曲中随机选择一首。
3. 创建并播放单个 `Audio` 对象。
4. 处理自动播放受阻与首次交互重试。
5. 在 `playing` 事件确认真正播放后写入状态并显示控件。
6. 响应暂停与继续操作。
7. 歌曲播放结束后保持停止，不清除已播放状态。

随机函数、状态存储和音频创建器以依赖形式传入核心逻辑，使行为可以在 Node 测试中稳定验证，不依赖真实浏览器音频设备。

## 数据流

进入首页时，代码先调用 `hasPlayed()`：

- 若为 `true`，立即结束，不创建音频、不显示控件。
- 若为 `false`，随机选取一个候选 URL 并尝试播放。
- 若播放成功并触发 `playing`，调用 `markPlayed()`，显示迷你便利贴控件。
- 若 `play()` 因浏览器策略被拒绝，则注册一次性的点击、触摸和按键监听；任一交互发生后移除全部监听并重试。
- 若重试后仍失败或资源加载失败，则保持安静，不显示错误，也不记录已播放。

只要音频曾真正开始，本次即视为已经播放过。即使用户很快暂停、离开页面或没有听完整首歌，后续进入首页也不会自动重播。

## 控件设计

播放器位于首页内容区域右下角，外形为轻微旋转的迷你便利贴，沿用现有黄色便利贴、胶带和手写字体语言。桌面端保持低存在感，移动端保留约 44 像素的可点击区域。

按钮只显示图标：

- 播放中显示暂停符号。
- 暂停时显示播放符号。
- 使用可访问名称向辅助技术说明“暂停背景音乐”或“继续背景音乐”。

不显示曲名、“正在播放”或“背景音乐已暂停”等文字。

## 异常与兼容处理

- `localStorage` 不可用时，状态存储退化为当前页面内的内存状态；不让存储异常阻断首页脚本。
- 自动播放被阻止时只等待首次有效交互重试，不连续弹窗或反复调用播放。
- 音频资源加载、解码或播放失败时静默结束，不记录已播放。
- 暂停后由用户点击继续；继续失败时维持暂停图标状态，不显示错误提示。
- 首页原有“换一批”文章功能保持独立，音乐初始化失败不能影响它。

## 测试策略

前端 Node 测试覆盖：

- 已播放状态为真时不选择或创建音频。
- 两个随机区间分别选择对应歌曲。
- 播放真正开始后才记录状态并显示控件。
- 首次自动播放被拒绝后，仅在首次用户交互时重试一次。
- 播放失败时不记录状态。
- 暂停与继续切换正确调用音频 API，并同步按钮状态。
- 歌曲结束后不循环、不播放第二首。
- `localStorage` 读写异常时安全退化。

Spring Boot 测试或静态检查覆盖：首页模板引用播放器模块、两首 MP3 可作为静态资源访问且 MIME 类型正确。最后运行完整 Java 与 Node 测试集，确认现有首页和其他功能没有回归。
