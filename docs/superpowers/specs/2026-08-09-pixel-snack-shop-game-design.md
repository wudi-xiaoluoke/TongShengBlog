# 像素零食店经营游戏设计

## 目标

将现有 `/game` 占位页改造成一个无失败压力、可持续经营的休闲零食店小游戏。玩家作为店长管理库存、服务顾客、安排进货并升级店铺；整体节奏接近“随手上线收菜”的轻量经营体验。

## 产品范围

第一版是纯前端单页游戏，继续使用现有 Spring MVC `/game` 路由，不新增账号、数据库或服务端接口。游戏状态保存在浏览器 `localStorage` 中。

第一版包括：

- 一张带街道和店铺内部的俯视像素场景。
- 店长角色和 3 类顾客。
- 6 种零食、对应货架库存与进货订单。
- 手动服务和升级后逐步启用的自动收银。
- 5 项升级：货架容量、配送速度、顾客数量、商品种类、自动收银。
- 无限经营、累计金币、口碑、店铺等级、图鉴和历史营业额。
- 自动存档、离线进货结算和“重新开店”。

不包含联网排行榜、多人互动、账号云存档、复杂员工系统或失败结局。

## 核心循环

1. 玩家花费金币创建进货订单。
2. 订单按真实时间倒计时；关闭页面后继续推进。
3. 到货后零食进入货架库存。
4. 顾客从街道出现，走进店门并前往目标货架。
5. 顾客生成包含 1–2 种零食的需求。
6. 前期由玩家选择顾客并点击正确货架完成交付；库存足够时顾客前往收银台。
7. 结账后玩家获得金币、口碑和营业额，顾客沿路径离店。
8. 玩家使用收益补货和升级，循环继续。

顾客等待过久会自行离开，但不会扣钱、清空进度或结束游戏。

## 场景与交互

主界面采用 Canvas 场景与 HTML 管理面板混合架构：

- Canvas 固定内部逻辑分辨率为 768×512，通过最近邻缩放适配容器。
- 场景上半部分是店铺内部，下半部分是街道，中间设置可见店门。
- 顾客状态依次为 `street`、`entering`、`shopping`、`queueing`、`checkout`、`leaving`。
- 顾客沿预定义路径点移动，动画帧由朝向和移动状态决定。
- 点击顾客显示需求；点击匹配的货架交付商品。
- HTML 面板展示金币、口碑、库存、进货、升级、账本、存档提示和重开入口。
- 手机端保持完整场景比例，经营面板移动到场景下方，不使用横向页面滚动。

## 自动化与平衡

- 初始阶段所有顾客由玩家手动服务。
- 自动收银升级后，按等级自动处理一定比例的库存充足订单。
- 自动化只替代交付和结账，不会自动购买进货订单，玩家仍需做经营决策。
- 基础进货时间从 30 秒到 3 分钟；配送升级按比例缩短剩余时间。
- 顾客到店间隔随店铺等级缩短，但同时在店顾客数量有上限，避免场景拥挤。
- 商品售价高于进货成本，稀有商品利润更高但配送更慢。
- 无限经营不设硬性每日目标、失败状态或强制广告机制。

## 美术资产

使用 ImageGen 生成项目内消费的像素素材：

- 一张俯视像素店铺与街道背景，不包含角色、文字、水印或 UI。
- 店长和 3 类顾客的四方向站立与行走精灵表。
- 货架、收银台、纸箱和 6 种零食图标。

所有素材使用统一的低分辨率像素风、暖色木质店铺配色和清晰硬边。需要透明背景的素材先生成在纯色键控背景上，再使用本地去背工具生成带 Alpha 的 PNG。生成结果必须复制到 `src/main/resources/static/images/game/` 后才能被项目引用。

## 代码结构

- `src/main/resources/templates/game/index.html`：页面结构、Canvas、管理面板和对话框。
- `src/main/resources/static/css/game.css`：像素化布局、响应式规则、按钮和面板样式。
- `src/main/resources/static/js/game/game-config.js`：商品、升级、路径点与平衡参数。
- `src/main/resources/static/js/game/game-state.js`：状态变更、库存、进货、收益、升级、存档和离线结算。
- `src/main/resources/static/js/game/game-scene.js`：素材加载、Canvas 绘制、路径移动、碰撞区域和角色动画。
- `src/main/resources/static/js/game/game-ui.js`：DOM 渲染、输入事件、面板切换和提示。
- `src/main/resources/static/js/game/main.js`：模块初始化、主循环和模块间协调。

各模块通过一个公开的游戏状态对象和明确事件函数协作，不直接复制或维护第二份状态。

## 状态与存档

存档包含版本号、金币、口碑、等级、库存、进货订单、升级等级、解锁商品、累计数据和最后保存时间。

- 关键操作后立即保存，并设置低频定时保存作为补充。
- 载入时根据最后保存时间结算已经完成的进货订单。
- 离线结算只完成进货，不模拟离线顾客消费，避免玩家离开期间库存被意外清空。
- 存档解析或版本校验失败时，将原字符串复制到备份键，再初始化新店并显示说明。
- “重新开店”必须二次确认，然后只清除本游戏使用的存档键。

## 错误处理

- 素材加载期间显示进度；关键背景或精灵加载失败时暂停主循环并提供重试按钮。
- 非关键零食图标失败时显示内置像素色块占位，不阻止经营。
- 进货、升级或交付条件不满足时只显示轻量提示，不修改状态。
- 页面隐藏时暂停 Canvas 动画；恢复可见时根据时间差更新倒计时和角色状态。

## 验证

- 为纯状态逻辑验证初始状态、买入、到货、交付、收益、升级、自动收银、离线结算和损坏存档恢复。
- 为模板和静态资源验证所有脚本、样式和图片引用存在。
- 手动检查顾客完整执行“街道出现 → 进门 → 货架 → 收银台 → 离店”。
- 检查 Canvas 最近邻缩放、桌面布局和手机布局。
- 运行完整 Maven 测试，确认博客、文章、分类和后台功能不受影响。

## 完成标准

用户访问 `/game` 后能看到清晰的俯视像素街道与店铺，顾客会实际走进店内消费；玩家可以补货、手动服务、获得收益、升级自动收银、关闭并重新打开页面继续经营，且整个循环没有失败压力。
