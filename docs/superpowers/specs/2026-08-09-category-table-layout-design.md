# 分类管理表格布局优化设计

## 目标

在保留现有暖色手账风格的前提下，改善分类管理页表格的列宽分配、行高和操作按钮布局。最终效果应兼顾信息密度与阅读舒适度，避免当前操作按钮纵向堆叠造成的大块留白。

## 范围

- 调整 `src/main/resources/templates/admin/categories.html` 中分类表格的结构类名与局部样式归属。
- 调整 `src/main/resources/static/css/admin.css` 中分类表格专用样式及窄屏响应规则。
- 不修改新增、保存、删除分类的表单行为、请求地址或后端逻辑。
- 不改变后台其他页面的现有表格布局。

## 布局方案

采用已确认的 A「单行均衡」方案：

- 保持排序、名称、描述、操作四列。
- 排序列固定为最窄宽度，名称列使用适中固定宽度，描述列占据剩余空间，操作列仅容纳两个按钮。
- 保存与删除按钮在同一行横向排列并垂直居中。
- 表格单行高度控制在约 58–64px；输入框使用统一高度、内边距、边框和圆角。
- 表头与输入内容保持清晰对齐，描述输入框随列宽伸缩。

## 响应式行为

- 桌面端四列保持单行展示，不让操作按钮换行。
- 窄屏下保留表格的合理最小宽度，并由现有表格容器提供横向滚动。
- 不通过压缩文字或缩小点击区域来强行适配窄屏。

## 实现边界

分类表格使用页面级 CSS 类进行定向控制，避免修改通用 `.actions`、`.btn` 或全局 `th/td` 规则后影响文章管理页。模板中的重复行内样式将迁移到分类表格专用类，以便桌面和窄屏规则集中维护。

## 验证

- 检查三条示例数据下的列宽、输入框基线、行高和按钮排列。
- 检查较长分类名称与描述不会挤压操作按钮。
- 检查窄屏下由表格容器横向滚动，内容不重叠、不裁切。
- 运行现有 Maven 测试，确认模板和后端行为未受影响。
