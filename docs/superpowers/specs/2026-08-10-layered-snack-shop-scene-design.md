# 分层零食店场景与可交互货架设计

## 目标

把现有“人物叠加在完整店铺图片上”的场景重构为分层 Canvas 经营场景。背景只承担环境展示，货架、收银台、商品状态与角色均为独立对象。顾客沿固定路线进店、取货、排队、结账和离店；玩家通过点击货架把仓库库存补到陈列库存。

## 范围

本次包含：

- 空店铺背景与独立货架素材。
- 六个固定货架及其点击、碰撞、遮挡和库存状态。
- 六条货架分支路线、公共进店路线、结账队列和离店路线。
- 仓库库存与货架库存分离。
- 旧存档迁移与新存档版本。
- 现有进货、升级、账本、离线配送和本地存档功能适配。

本次不包含：

- 自由摆放或旋转家具。
- 玩家控制人物自由行走。
- 完整瓦片地图编辑器。
- 多楼层、扩建房间或联网存档。

## 场景架构

Canvas 继续使用 768×512 的逻辑坐标，按以下顺序绘制：

1. **环境背景层**：墙面、木地板、店门、人行道、斑马线和街道，不包含人物、货架或收银台。
2. **后排家具层**：根据对象的 `zBase` 与角色脚底坐标排序，绘制可能位于角色后方的货架和装饰。
3. **角色层**：店长和顾客，根据脚底 `y` 坐标排序。
4. **前排家具层**：绘制脚底在家具后方时应遮挡角色的家具前沿。
5. **状态与交互层**：选中描边、库存状态、缺货气泡、需求气泡和排队提示。

场景对象使用统一结构：

```js
{
  id,
  type,
  x,
  y,
  width,
  height,
  hitbox,
  collisionBox,
  zBase
}
```

货架在此基础上增加 `productId`、`approachPoint` 和 `routeId`。

## 货架布局与状态

店内设置六个固定货架，每个商品对应一个货架。货架不能移动，货架位置、停靠点和路线配置集中定义在 `game-config.mjs`，绘制和命中逻辑不硬编码商品坐标。

每个货架保存：

- `productId`：陈列商品。
- `quantity`：当前陈列数量。
- `capacity`：陈列上限。
- `displayState`：由数量比例计算，不写入存档。

视觉状态规则：

| 状态 | 比例 | 展示 |
| --- | --- | --- |
| empty | 0 | 空木架、缺货标志 |
| low | 1%–39% | 少量商品，空位明显 |
| half | 40%–79% | 商品约占半架 |
| full | 80%–100% | 商品排列完整 |

货架底图使用独立透明素材，商品陈列通过程序重复绘制现有商品图标实现。这样同一货架素材可以服务所有商品和四种数量状态。

## 货架交互

点击货架后：

- 货架出现高亮描边。
- 右侧经营区切换到货架补货面板。
- 面板显示商品名称、仓库数量、货架数量、容量和状态。
- 提供“补 1 件”“补 5 件”“补满”按钮。

补货数量取按钮目标值、仓库库存和货架剩余容量三者的最小值。仓库为空或货架已满时按钮禁用，并给出明确提示。点击场景空白处取消选择；点击顾客则切换到顾客信息，货架选择被清除。

## 库存模型

状态从单一 `inventory` 调整为：

```js
{
  warehouseInventory: { [productId]: number },
  shelfInventory: { [productId]: number },
  saveVersion: 2
}
```

库存流转：

```text
进货订单 -> 仓库库存 -> 玩家补货 -> 货架库存 -> 顾客取货 -> 结账收入
```

- 配送完成只增加 `warehouseInventory`。
- 补货同时减少仓库库存并增加货架库存，总数守恒。
- 顾客取货只减少货架库存。
- 多商品订单通过 `reservedItems` 保证要么全部预留、要么完全不扣货。
- 顾客成功完成结账后增加金币、营业额、口碑和服务人数。
- 顾客缺货离店不产生收入，并增加流失人数、轻微降低口碑。
- “扩容货架”升级提高所有货架的容量。
- “自动收银”升级缩短结账时长。

## 顾客固定路线

路线采用命名节点和固定 waypoint 数组，不做自由寻路。

公共节点：

```text
街道出生点 -> 人行道 -> 斑马线 -> 店门 -> 店内入口节点
```

进入店内后，根据目标商品选择 `shelf-1` 至 `shelf-6` 分支。每条分支由入口节点、通道转弯点和货架停靠点组成，所有节点位于可行走区域，不能与货架 `collisionBox` 相交。

每个货架只有一个取货停靠点，并配有一个通道等待点。同一时间只允许一名顾客占用停靠点；后到顾客在等待点停留，前一名顾客离开后再进入，避免角色重叠。

正常流程：

```text
street -> entering -> browsing -> picking -> queueing -> checkout -> leaving -> done
```

缺货流程：

```text
street -> entering -> browsing -> outOfStock -> leaving -> done
```

顾客到达货架后检查陈列库存：

- 有货：扣除请求数量，显示持有商品，前往收银台队列。
- 缺货：显示缺货气泡，停留数秒后沿离店路线离开。

顾客默认购买一种商品；店铺等级提高后可以出现两种商品的订单。多商品订单在顾客进入店内时执行一次原子预留：只有所有目标货架库存都充足时，才将数量从可售库存转入该顾客的 `reservedItems`，随后按固定顺序访问对应货架。任一商品不足时不扣除任何库存，顾客只前往第一个缺货货架展示缺货反馈后离店。顾客异常移除时，尚未结账的预留商品退回对应货架。

## 收银台队列

收银台前设置三个固定排队点。顾客进入队列后按到达顺序占用最靠前的空位；前方顾客离开后，其余顾客依次前移。只有队首顾客进入 `checkout`。

初始结账时间保持休闲节奏；自动收银每级降低结账时长，但保留可见的停顿和付款动作。队列满时，新顾客仍可在货架处等待，直到出现空位，不允许多个角色重叠在同一排队点。

## 角色和家具遮挡

所有角色以脚底坐标作为深度基准。货架拆为主体和前沿两个绘制阶段：角色在货架后方时由货架主体遮挡，在货架前方时绘制在货架之上。角色永远不能进入家具碰撞区域。

现有角色图集继续使用真实列中心取帧，避免恢复等宽切片造成断肢或串帧。

## 素材计划

使用内置 ImageGen 生成一张与现有暖色像素风一致的空店铺背景：保留墙面、木地板、门、人行道、街道和斑马线，移除全部人物、货架、收银台和可交互家具。

另外生成或整理一套透明背景的独立货架与收银台素材。透明素材先在纯色 chroma-key 背景生成，再使用标准去背脚本转为透明 PNG。最终素材必须放入项目 `static/images/game` 目录，并在浏览器中检查边缘和像素缩放。

## 存档迁移

读取无 `saveVersion` 的旧存档时执行一次迁移：

1. 读取旧 `inventory[productId]`。
2. 将不超过当前货架容量的数量放入 `shelfInventory`。
3. 超出容量的数量放入 `warehouseInventory`。
4. 保留金币、口碑、等级、升级、统计、账本和运输中订单。
5. 将运输中订单完成后的目标改为仓库库存。
6. 写入 `saveVersion: 2` 并保存。

损坏存档继续复制到备份键，再恢复初始状态。迁移过程不得修改旧备份内容。

全新游戏保持原有开局节奏：草莓糖货架放置 5 件、原味薯片货架放置 3 件，其余货架为空，仓库库存为 0。

## 错误与边界处理

- 背景或家具素材加载失败：保留加载错误层并提供重试。
- 点击不可见、未解锁或无商品货架：不改变库存。
- 仓库库存不足：补充实际可用数量；为零时提示“仓库缺货”。
- 货架已满：不扣仓库库存。
- 顾客请求数量大于货架库存：按缺货流程处理，不部分扣货。
- 队列拥堵：顾客等待，不穿过家具或其他顾客。
- 目标货架被占用：顾客停在该货架的通道等待点，不与正在取货的顾客重叠。
- 页面关闭或角色异常移除：未结账的 `reservedItems` 退回货架。
- 页面隐藏或恢复：继续使用时间差结算配送，角色动画暂停后恢复。

## 测试与验收

自动化测试覆盖：

- 六条货架分支的完整状态流转。
- 所有 waypoint 均不与家具碰撞区域相交。
- 队列顺序、前移和队首结账。
- 仓库到货架的数量守恒及容量限制。
- `empty`、`low`、`half`、`full` 阈值。
- 正常取货、缺货离店和多件请求不可部分成交。
- 自动收银升级对结账时间的影响。
- 旧存档到版本 2 的迁移。
- 新存档序列化、损坏存档恢复和离线配送。

浏览器验收覆盖：

- 背景中无烘焙人物或货架。
- 六个货架可点击且命中区域准确。
- 补货后货架状态立即变化。
- 顾客只走固定通道，不穿过货架。
- 多名顾客按顺序排队且不重叠。
- 人物与货架前后遮挡正确。
- 桌面双栏和手机单栏均无横向溢出。

## 完成标准

玩家可以完成“进货到仓库、点击货架补货、观察货架由空变满、顾客沿固定路线取货并排队结账”的完整经营循环。场景中的货架、商品状态和顾客行为全部来自游戏状态，而不是背景图片中的静态内容。
