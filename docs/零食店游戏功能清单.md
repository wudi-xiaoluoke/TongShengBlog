# 同生零食铺 · 功能清单（视觉重做防护手册）

> 目的：游戏要做**视觉重做**。本文把「功能性内容」逐项固化下来——重做时**表现层（CSS/画布绘制/动画/文案版式）可以随便换**，但凡是标了 🔒 的条目属于**功能契约**，动了就会坏。
> 基线：分支 `feature/snack-shop-pixel-qstyle`，commit `f721b7f`（2026-09-07）。单测 122/122 通过。

---

## 0. 重做总原则

1. **三层结构**：`game-config.mjs`（数值/规则，纯函数）→ `game-state.mjs`（状态与业务操作）→ `game-ui.mjs / game-scene.mjs / main.mjs`（渲染与交互）。视觉重做只应触碰第三层。
2. **JS 靠 DOM 契约工作**：`game-ui.mjs` 通过 `getElementById` 和**事件代理**（靠 `data-*` 属性匹配点击目标）工作。重做 HTML 时，**第 6 节的 id 和 data-* 一个都不能少**（可以改 class 和样式，不能改 id/data-*）。
3. **数据签名防重建**：界面每 250ms 刷新一次。货架气泡、深夜订货表格、书签都靠「数据签名」判断是否重建 DOM。重做时**必须保留这套机制**（见 §7.1），否则下拉框/悬停态会被刷新打断（历史上已踩过 3 次坑）。
4. **动画只许用 transform**：headless 截图和部分环境下 opacity 入场动画会冻在中间帧；所有 UI 入场动画只用 `transform` 位移/缩放。
5. 存档兼容：`state` 字段名即存档格式（§5），重做不得改字段名；新字段必须能从旧档兜底。

## 2. 核心玩法系统（数值均出自 game-config.mjs）

### 2.1 经济系统
- **货币**：金币（开局 200）。来源=顾客结账；支出=进货/升级/加柜/房租。
- **口碑**：成交 +1/单；达日目标 +5；交不起房租 −8；顾客生气离店 −2。口碑 ≥12 后有 12% 概率刷 VIP。
- **等级**：每服务 8 位顾客升 1 级。等级（+零食图鉴升级）决定商品解锁。
- **房租**：`50 + 35×等级`/天；**日目标 = 房租×2**，达标口碑+5。
- **10 种零食**，每单固定 10 件，各有进货价/售价/配送时长/解锁等级/分类：

| 商品 | 分类 | 进货价 | 售价 | 配送 | 解锁等级 |
|---|---|---|---|---|---|
| 草莓糖 | 糖果 | 20 | 36 | 30s | 1 |
| 原味薯片 | 膨化 | 30 | 50 | 45s | 1 |
| 脆脆海苔 | 膨化 | 38 | 62 | 60s | 2 |
| 橘子汽水 | 饮品果冻 | 45 | 72 | 75s | 2 |
| 黄油饼干 | 烘焙坚果 | 55 | 88 | 90s | 3 |
| 香脆花生 | 烘焙坚果 | 42 | 68 | 70s | 3 |
| 云朵棉花糖 | 糖果 | 40 | 66 | 75s | 3 |
| 劲爆辣条 | 膨化 | 50 | 80 | 90s | 4 |
| 水果果冻 | 饮品果冻 | 68 | 105 | 120s | 4 |
| 黑巧克力 | 糖果 | 75 | 118 | 105s | 5 |

- 分类体系 🔒：`all/sweet/puffed/bake/drink`（糖果/膨化/烘焙坚果/饮品果冻），用于深夜订货书签、手机两页的分类条。

### 2.2 时间与日夜循环
- 一个营业日 = **实时 3 分钟** = 游戏内 09:00→21:00（`gameClock` 换算，所有时间显示统一走它）。
- 到 21:00 不直接结算 → 进入**凌晨订货过场**（`state.dayBreak=true`，时间冻结）：夜幕手账双页 → 玩家下进货单 → 点「开门营业」→ 结算房租/翻日/换季播报 → 回到 09:00。刷新页面若停在凌晨态要能恢复夜幕画面。
- **5 时段**（影响客流间隔、同店上限、客群权重）：

| 时段 | 范围 | 间隔倍率 | 上限倍率 | 主要客群 |
|---|---|---|---|---|
| 早晨 | 9–11 | ×1.25 | ×0.8 | 邻居 |
| 中午 | 11–14 | ×0.6（高峰） | ×1.2 | 职员 |
| 下午 | 14–17 | ×0.8 | ×1.1 | 学生 |
| 傍晚 | 17–19 | ×1.3（最空） | ×0.7 | 邻居 |
| 晚上 | 19–21 | ×0.9 | ×1.0 | 职员 |

- **季节跟真实月份**（3–5 春 / 6–8 夏 / 9–11 秋 / 12–2 冬），影响整体客流倍率（夏 1.15 最旺、冬 0.85 最淡）+ 场景表现（色调/植物叶色/天气粒子：花瓣/光斑/落叶/雪花）。换天时刷新季节并播报。
- 客流公式：`间隔 = max(2.5s, (10s − 招牌×1.1s) × 时段倍率 ÷ 季节倍率)`；`同店上限 = min(5, 2+招牌级) × 时段系数`（满招牌中午可到 6）。

### 2.3 顾客系统（状态机 🔒）
- 3 种客群变体（学生/邻居/职员，不同配色）+ VIP 金冠贵客。
- 阶段流转：`street → entering → browsing(去主货柜) → picking → queueing/waitingQueue → checkout → leaving → done`；缺货走 `outOfStock` 直接离店。
- 行为细节：多顾客买同一种零食会**占同一货架的等待点**（`retargetShelfWaiters`）；收银台**排队**（`promotePendingQueue`）；顾客请求 1–2 种零食（等级 ≥3 时 32% 概率买两样）；VIP 一次买 2–3 样、付款 ×1.5、耐心 ×0.7。
- **耐心**：基础 50s，在排队/等待时消耗，头顶有耐心条；耗尽生气离店（口碑−2）。等待耗时占比 <45% 时 12% 概率给小费。
- **点顾客不响应**（纯观赏，历史上点击查看功能已被需求移除）。
- 顾客只买**货架上摆着的**零食。

### 2.4 货架/排面系统
- 柜位：开局 6 柜，上限 10 柜（两排×5）；每柜 12 格 = 4 行 × 3 格，**一行放一种**，单品容量 = 行数×3×每格件数。
- 加柜价：180 起，每柜 ×1.6；加柜时可顺带上架一种新零食（或纯空柜，全部零食容量都涨）。
- 自动排面：零食按 `(柜×4+行) % 种类数` 轮转填行；种类少时同种零食多占行 → 容量更大；主货柜贪心分配让动线分散。
- **玩家自定义排面**：点柜弹出气泡，每行一个下拉换种类（`swapShelfRow`）；首次修改后存进 `shelfPlan`；换掉某零食的全部行后，其货架存货自动退回仓库。
- 货架三库存：`shelfInventory`（在架）/ `reservedInventory`（顾客已取未结）/ `warehouseInventory`（仓库）。补货受 `容量 − 在架 − 预留` 约束。

### 2.5 5 种店铺升级（价格 ×1.65/级）
| 升级 | 基价 | 效果 |
|---|---|---|
| 扩容货架 shelf | 250 | 每级每格多放 1 件 |
| 配送小车 delivery | 300 | 每级配送时间 −12%（下限 45%） |
| 街边招牌 traffic | 300 | 来客更频繁+上限提高 |
| 零食图鉴 catalog | 450 | 提前解锁商品 |
| 自动收银 checkout | 350 | 自动服务部分顾客（缩短结账） |

## 4. 主循环与存档机制（main.mjs）🔒

- `requestAnimationFrame` 主循环：生成顾客（受时段/季节/上限约束）→ 顾客模拟 → 到货结算 → 日推进 → Canvas 重绘 → 每 250ms 刷 DOM。
- 自动存档：每次状态变更、每 15s 定时、`beforeunload`、切后台时存 `localStorage`。
- **云存档**：登录用户启动时 `GET /api/game/save` 拉云端档（云档优先，镜像到本地）；之后每次存档**防抖 3s** `PUT` 上云，状态栏显示「已同步云端 ☁」。
- 存档恢复：损坏档自动备份到 `tongsheng.snackShop.backup` 并开新店提示；v1 老档自动迁移。
- 店主名牌 `#player-chip`：登录后显示「店主：XX · 已接续云端档」。

## 7. 历史踩坑（重做时必须继承的解决方案）⚠️

### 7.1 250ms 刷新 vs 交互态（三次教训）
- 书签闪烁 → 书签只在打开/点击时渲染一次；
- 下拉框被刷新关掉 → `renderShelf` 加**结构签名**（柜位+各行种类+解锁数，**不含库存数字**），签名不变不重建；库存文案/按钮置灰改为 `querySelector` **定点更新**；
- 深夜订货表格同理有 `nightSig`。
- **重做任何 250ms 会刷新的面板时，都必须沿用「结构签名 + 定点更新」模式。**

### 7.2 其他
- CSS opacity 入场动画在 headless/部分环境冻中间帧 → 动画只用 transform。
- 气泡定位 `positionPopovers` 按 canvas 768×512 坐标换算贴在货架下方；小屏(<700px)回退文档流。
- 同一文件多处 Edit 不能并行（会互相覆盖）——改代码时串行。
- 静态资源版本号：`game.css(v=…)` / `main.mjs(v=…)` 每次改动要升级并同步 `target/classes`。
- 验证：`node --test tests/*.test.mjs`（122 个）；headless 截图用已缓存的 Playwright Chromium + `--virtual-time-budget`；交互态验证用「同源探针页 + 注入脚本 + `*{animation:none}`」。
